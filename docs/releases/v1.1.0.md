# Workflow v1.1.0 — 21 October 2026

Published: https://github.com/tech-officer/workflow/releases/tag/v1.1.0

TechOfficer workflow v1.1.0 adds reproducible workflow export and safe, reviewable upgrades for existing projects.

Source: `db6d10644fc25e1df476436eb91ec0062e790ef0` (merged PR #7). Contract version remains **2.2**; the release version and contract version are separate.

### Changes
- Deterministic rendered exports with source/rendered hashes, Git modes and explicit inputs.
- A shared managed-file map for the installer and exporter, compatible with TechOfficer's B-511 upgrade planner.
- Optional explicit UTC render time, input validation and destination-link checks.
- Fresh documents use mode0644; existing custom documents and their modes remain preserved.

### Compatibility and migration
Readers support both Contract2.2 queue forms; producers continue writing front-matter queues. This release does not introduce Contract2.3 or automatically migrate project records.

For existing projects, use reviewed per-project subset manifests and upgrade PRs. Keep project-specific AGENTS, plans, founder messages, decisions, queues and custom templates intact. Unknown historical installations remain unknown. Do not force-install the kit over an existing project.

Already reviewed adopter baselines pinned to the source commit above remain valid. Their original export labels may say unpublished because that was true at export time; do not rewrite immutable records just to change that historical label.

[Export, migration, pin/defer and rollback instructions](https://github.com/tech-officer/workflow/blob/db6d10644fc25e1df476436eb91ec0062e790ef0/docs/releases/upgrade-candidates.md). Before merge, verify forward/reverse changes on the exact disposable tree; after merge, use a reviewed revert PR that preserves later customizations.
